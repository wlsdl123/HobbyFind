# 2. 상세 Use Case 시나리오 (Detailed Use Case Scenarios)

## UC-01 서비스 접속 및 루트페이지 탐색

### 목적

사용자가 서비스 소개와 전체 취미 목록을 확인한다.

### 주요 액터

* 비로그인 사용자

### 관련 페이지

* `/`

### 성공 시 결과

* 전체 취미 목록이 표시된다.

---

## UC-02 카테고리 선택

### 목적

사용자가 원하는 카테고리의 취미만 확인한다.

### 주요 액터

* 비로그인 사용자

### 관련 페이지

* `/sports`
* `/intellectual`
* `/arts`

### 성공 시 결과

* 선택한 카테고리의 취미만 표시된다.

---

## UC-03 로고를 통한 홈 이동

### 목적

사용자가 언제든지 루트 페이지로 이동한다.

### 주요 액터

* 비로그인 사용자

### 성공 시 결과

* 루트 페이지가 표시된다.

---

## UC-04 취미 카드 탐색

### 목적

사용자가 취미 목록을 확인한다.

### 주요 액터

* 비로그인 사용자

### 성공 시 결과

* 취미 카드가 그리드 형태로 표시된다.

# 3. 주요 단계 및 이벤트 흐름 (Main Steps and Flow of Events)

## UC-01 루트페이지 탐색

| 단계 | 사용자      | 시스템              |
| -- | -------- | ---------------- |
| 1  | 사이트 접속   | 루트 페이지 요청        |
| 2  | -        | Top Bar 표시       |
| 3  | -        | Hero 섹션 표시       |
| 4  | -        | 전체 취미 카드(18개) 표시 |
| 5  | 취미 목록 확인 | 화면 유지            |

---

## 이벤트 흐름

```text
사용자 접속
        │
        ▼
루트 페이지 로드
        │
        ▼
Hero 표시
        │
        ▼
Top Bar 표시
        │
        ▼
전체 취미 Grid 표시
```

---

## UC-02 카테고리 선택

| 단계 | 사용자        | 시스템          |
| -- | ---------- | ------------ |

| 2  | 운동형 선택     | `/sports` 이동 |

| 4  | -          | 운동형 취미 6개 표시 |

동일한 흐름은 지능형 및 예술형에도 적용된다.

---

## 이벤트 흐름

```text
카테고리 클릭
        │
        ▼
URL 변경
        │
        ▼
카테고리 페이지 로드
        │
        ▼
소개 문구 표시
        │
        ▼
취미 Grid 표시
```

# 4. 대체 흐름 및 엣지 케이스 (Alternative Flows and Edge Cases)

| 상황                     | 시스템 동작             |
| ---------------------- | ------------------ |
| 사용자가 이미 현재 카테고리를 다시 클릭 | 동일 페이지 유지          |
| 루트 페이지에서 로고 클릭         | 루트 페이지 유지          |
| 잘못된 URL 접근             | 404 페이지 표시         |
| 브라우저 새로고침              | 현재 URL 기준 페이지 재렌더링 |
| 브라우저 뒤로가기              | 이전 페이지 복원          |
| 브라우저 앞으로가기             | 다음 페이지 복원          |
| 화면 크기 변경               | 반응형 레이아웃 재배치       |

---

# 5. 사전조건과 사후조건 (Preconditions and Postconditions)

## UC-01 루트페이지 탐색

### 사전조건

* 웹 브라우저 사용 가능
* 서비스 URL 접근 가능

### 사후조건

* 루트 페이지가 정상적으로 표시된다.
* 전체 취미 목록을 확인할 수 있다.

---

## UC-02 카테고리 탐색

### 사전조건

* 서비스 접속 완료
* Top Bar가 표시됨

### 사후조건

* 선택한 카테고리 페이지가 표시된다.
* 해당 카테고리 취미만 노출된다.

---

## UC-03 로고 클릭

### 사전조건

* Header가 표시됨

### 사후조건

* 루트 페이지로 이동한다.

---

# 6. 비즈니스 규칙 및 제약사항 (Business Rules and Constraints)

## 서비스 이용 규칙

* 로그인 없이 모든 기능 이용 가능
* 모든 페이지는 공개 접근 가능
* 취미 목록은 정적 데이터로 제공

---

## 카테고리 규칙

| 규칙     | 내용    |
| ------ | ----- |
| 카테고리 수 | 3개 고정 |
| 운동형    | 6개    |
| 지능형    | 6개    |
| 예술형    | 6개    |
| 전체 취미  | 18개   |

---

## 고정 취미 목록

### 운동형

* 조깅 / 러닝
* 요가
* 수영
* 자전거
* 클라이밍
* 댄스

### 지능형

* 독서
* 퍼즐
* 체스
* 프로그래밍
* 외국어 학습
* 사진 촬영

### 예술형

* 그림 그리기
* 악기 연주
* 요리
* 서예
* 도자기 만들기
* 정원 가꾸기

---

## 제약사항

* 로그인 기능 없음
* 회원가입 없음
* 검색 기능 없음
* 취미 상세 페이지 없음
* 데이터 수정 없음
* 관리자 기능 없음
* 취미 목록 변경 불가

---

# 7. 예외 처리 절차 (Exception Handling Procedures)

| 예외 상황                | 처리 절차                     |
| -------------------- | ------------------------- |
| 존재하지 않는 URL          | 404 페이지 표시                |
| 네트워크 오류              | 오류 안내 메시지 표시 및 새로고침 유도    |
| 이미지 로드 실패            | 대체 이미지 또는 플레이스홀더 표시       |
| 데이터 로드 실패(정적 데이터 누락) | 빈 목록과 오류 메시지 표시           |
| 브라우저 지원 문제           | 기본 HTML 콘텐츠 제공 및 기능 제한 안내 |

---

# 8. UI 고려사항 (User Interface Considerations)

## Header

* 모든 페이지에서 동일한 위치 유지
* 현재 선택된 카테고리 강조 표시
* 로고 클릭 시 홈 이동

---

## Hero

* 루트 페이지에서만 표시
* 서비스 목적을 한 문장으로 전달

---

## 취미 카드

구성 요소

* 대표 이미지
* 취미명
* 카테고리 배지

특징

* 동일한 카드 크기 유지
* CSS Grid 기반 정렬
* 모바일부터 데스크톱까지 반응형 배치

---

## 반응형 레이아웃

| 화면 크기                 | Grid |
| --------------------- | ---- |
| Mobile (320~767px)    | 1열   |
| Tablet (768~1023px)   | 2열   |
| Desktop (1024~1439px) | 3열   |
| Wide (1440px 이상)      | 4열   |

---

## 접근성

* 키보드(Tab) 탐색 지원
* 카테고리 버튼에 `aria-label` 제공
* 이미지 `alt` 속성 제공
* 명확한 포커스 스타일 적용
* WCAG 2.1 AA 수준의 명암 대비 권장

---

# 9. 데이터 요구사항 및 데이터 흐름 (Data Requirements and Data Flow)

## 데이터 요구사항

서비스는 **고정된 정적 데이터셋**을 사용한다.

| 항목     | 내용                |
| ------ | ----------------- |
| 카테고리   | 운동형, 지능형, 예술형     |
| 총 취미 수 | 18개               |
| 저장 방식  | 정적 TypeScript 데이터 |
| 데이터 변경 | 불가                |

---

## 데이터 흐름

```text
정적 취미 데이터
        │
        ▼
Next.js 페이지
        │
        ▼
카테고리 필터 적용
        │
        ▼
Grid 컴포넌트
        │
        ▼
사용자 화면 출력
```

---

## 페이지별 데이터

| 페이지             | 데이터       |
| --------------- | --------- |
| `/`             | 전체 취미 18개 |
| `/sports`       | 운동형 6개    |
| `/intellectual` | 지능형 6개    |
| `/arts`         | 예술형 6개    |

# 10. 보안 및 개인정보 고려사항 (Security and Privacy Considerations)

## 개인정보

* 로그인 기능 없음
* 회원가입 없음
* 개인정보 입력 없음
* 개인정보 저장 없음

---

## 보안

* 서버 인증 불필요
* 공개 페이지만 제공
* 정적 데이터만 사용
* 외부 API 호출 없음

---

## 데이터 무결성

* 취미 목록은 읽기 전용
* 클라이언트에서 수정 불가
* 배포 시 포함된 정적 데이터만 사용

---

## SEO 및 웹 표준

* 각 페이지별 고유 `title` 및 `meta description` 제공
* 시맨틱 HTML(`header`, `main`, `section`, `footer`) 사용
* 검색 엔진이 각 카테고리 페이지를 독립적으로 인덱싱할 수 있도록 URL 구조 유지
